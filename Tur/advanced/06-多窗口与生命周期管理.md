# 进阶 06 · 多窗口与生命周期管理

> 目标：基础篇埋了个坑——「`glfwInit` 是进程级的，`shutdown` 不调 `glfwTerminate`」。
> 这一篇把这个坑彻底填上：讲清楚窗口级资源和进程级资源的区别，给出多窗口、引用计数的正确工程化方案。

---

## 6.1 两类资源：窗口级 vs 进程级

GLFW 的 API 里，资源分两层：

| 资源 | 级别 | 创建 | 销毁 |
|---|---|---|---|
| GLFW 库本身（事件系统、错误回调、游戏手柄子系统） | **进程级** | `glfwInit()` | `glfwTerminate()` |
| 窗口（含 GL 上下文） | **窗口级** | `glfwCreateWindow()` | `glfwDestroyWindow()` |
| 游标准/光标对象 | **进程级** | `glfwCreateStandardCursor()` | `glfwTerminate()` 时全销毁 |

关键陷阱：

- `glfwTerminate()` **会销毁所有还没销毁的窗口、所有光标**。它是核弹，不是手术刀。
- 一个进程里 `glfwInit` 可以重复调用——官方文档：库只需初始化一次，对已初始化的库再调会直接返回
  `GLFW_TRUE`（**没有内部引用计数**，引用计数是下面方案 A/B 自己实现的）——但 `glfwTerminate` 一次就把整个库拆了。

所以规则是：

> **`glfwInit` / `glfwTerminate` 配对出现一次（进程级），`glfwCreateWindow` / `glfwDestroyWindow` 每个窗口配对一次。**

---

## 6.2 错误示范：为什么不能在窗口析构里调 terminate

```cpp
GLFWManager::~GLFWManager() {
    glfwDestroyWindow(m_window);
    glfwTerminate();          // ❌ 灾难
}
```

后果：

```cpp
GLFWManager w1; w1.init(...);   // 窗口 A
GLFWManager w2; w2.init(...);   // 窗口 B
// w2 析构 → glfwTerminate() → 把窗口 A 也一起销毁了！
// w1 析构 → glfwDestroyWindow(已销毁的窗口) → UB / 崩溃
```

[基础篇 04 的 4.4 节](../basics/04-实现基础GLFWManager.md) 的 `static bool` 守卫解决了「init 只调一次」，但没解决「terminate 何时调」。
正确答案是：**terminate 不该归窗口管，归进程管。**

---

## 6.3 方案 A：全局 App 层管 init/terminate（推荐）

引擎最外层有个 `Application`（或专门的 `GLFWRuntime`），它独占 init/terminate，所有窗口在它的生命周期内活动：

```cpp
class GLFWRuntime {
public:
    GLFWRuntime() {
        glfwSetErrorCallback(errorCallback);
        if (!glfwInit()) throw std::runtime_error("GLFW init failed");
        s_count++;
    }
    ~GLFWRuntime() {
        if (--s_count == 0) {
            glfwTerminate();
        }
    }
    GLFWRuntime(const GLFWRuntime&) = delete;
    GLFWRuntime& operator=(const GLFWRuntime&) = delete;
private:
    static int s_count;   // 进程内可能多个 runtime 实例（库嵌套），引用计数
};
int GLFWRuntime::s_count = 0;
```

`main` 里：

```cpp
int main() {
    GLFWRuntime runtime;          // 进程级：init，RAII

    Window w1; w1.init({"Win1", 800, 600});
    Window w2; w2.init({"Win2", 400, 300});

    // ... 两个窗口的主循环

    // w2、w1 析构 → 各自 DestroyWindow
    // runtime 析构 → 引用计数归 0 → glfwTerminate
}
```

窗口类此时**完全不管 init/terminate**，只管自己的窗口：

```cpp
Window::~Window() {
    m_context.reset();            // 先释放上下文（[04 篇 4.6 节](04-分离RenderContext.md)）
    if (m_window) { glfwDestroyWindow(m_window); m_window = nullptr; }
    // 没有 glfwTerminate！
}
```

职责清爽：`GLFWRuntime` 管进程级，`Window` 管窗口级。

---

## 6.4 方案 B：窗口内部引用计数（不需要 App 层时）

如果不想引入 `GLFWRuntime`，可以让每个 `Window` 用静态引用计数自管 init/terminate：

```cpp
class Window {
    static int s_glfwRefcount;
public:
    bool init(const Props& p) {
        if (s_glfwRefcount == 0) {           // 第一个窗口负责 init
            glfwSetErrorCallback(errorCallback);
            if (!glfwInit()) return false;
        }
        ++s_glfwRefcount;
        m_window = glfwCreateWindow(...);
        // ...
    }
    void shutdown() {
        if (m_context) m_context.reset();
        if (m_window) { glfwDestroyWindow(m_window); m_window = nullptr; }
        if (--s_glfwRefcount == 0) {         // 最后一个窗口负责 terminate
            glfwTerminate();
        }
    }
};
int Window::s_glfwRefcount = 0;
```

效果同方案 A，但耦合回到了窗口类。多窗口时好用，但和「Window 抽象接口」（[02 篇](02-窗口抽象层与接口设计.md)）混着用要小心：
引用计数应该放在**具体实现**（`GLFWWindowImpl`）里，不能放在抽象接口。

> 💡 推荐方案 A。它把「进程级资源」这个概念显式建模成一个类，比隐藏在静态变量里更清晰、更好测。

## 6.5 多窗口的渲染循环

多窗口 = 多个上下文。画到哪个窗口，先把那个上下文设为 current：

```cpp
std::vector<std::unique_ptr<Window>> windows;
windows.push_back(Window::create({"Main", 1280, 720}));
windows.push_back(Window::create({"Tools", 400, 600}));

while (!windows.empty()) {
    // 删掉已经关掉的窗口
    windows.erase(
        std::remove_if(windows.begin(), windows.end(),
            [](auto& w){ return w->shouldClose(); }),
        windows.end());

    for (auto& w : windows) {
        w->makeContextCurrent();     // ← 切换当前上下文
        renderTo(w);                 // 渲染到这个窗口
        w->swapBuffers();
    }
    glfwPollEvents();                // 进程级，所有窗口的事件一次拉取
}
```

要点：
- `glfwPollEvents()` 是**进程级**的，拉取所有窗口的事件——只需调一次，别每个窗口调。
- 每个窗口有自己的 framebuffer / GL 状态，画前要 `makeContextCurrent`。
- 资源（纹理、shader）默认是**绑定在上下文上的**，两个窗口不共享。要共享需在 `glfwCreateWindow` 第 5 个参数传一个已有窗口（共享上下文）。

```cpp
GLFWwindow* w2 = glfwCreateWindow(w, h, "w2", nullptr, w1);   // w2 共享 w1 的资源
```

> ⚠️ 共享上下文后，两个窗口用同一套 GL 对象，但要小心**同步**：跨上下文访问共享资源可能需要 GL 同步原语（fence）。

## 6.6 线程注意

GLFW 有两条铁律：

1. **初始化、终止、事件处理、窗口/光标/上下文的创建与销毁必须在主线程**（官方文档明文；工作线程里调
   `glfwCreateWindow` 不行）。少数函数官方允许任意线程：`glfwPostEmptyEvent`（用来唤醒阻塞中的
   `glfwWaitEvents`）、`glfwMakeContextCurrent`/`glfwGetCurrentContext`、`glfwSwapBuffers`/`glfwSwapInterval`、
   计时函数与 Vulkan 查询。入门期记住保守版：**主线程包办一切窗口事务，工作线程只调 `glfwPostEmptyEvent`**。
2. **一个上下文 current 在一个线程**。你不能两个线程同时 current 同一个上下文。

所以多窗口 ≠ 多线程渲染。要并行渲染，常见做法：主线程管窗口 + 提交命令，工作线程做资源加载 / 物理计算。
多线程的完整方案见 [07 篇 性能与多线程](07-性能与多线程.md)。

## 6.7 完整生命周期总览

把窗口子系统的资源生命周期画成一张图：

```
进程启动
   │
   ▼
GLFWRuntime()                       ← glfwInit（进程级，仅一次）
   │
   ├─ Window w1                     ← glfwCreateWindow（窗口级）
   │    └─ RenderContext            ← makeCurrent + glewInit（一次）
   │         └─ LayerStack
   │              ├─ GameLayer
   │              └─ ImGuiLayer
   │
   ├─ Window w2 (可选)
   │
   │  ╔════════ 主循环 ════════╗
   │  ║ Input::nextFrame       ║
   │  ║ pollEvents (进程级)     ║
   │  ║   └─ Event → 各 Layer  ║
   │  ║ onUpdate (各层)         ║
   │  ║ render                  ║
   │  ║ swapBuffers (各窗口)    ║
   │  ╚═══════════════════════╝
   │
   ├─ w1.shutdown()                  ← Context.reset → DestroyWindow（窗口级）
   ├─ w2.shutdown()
   │
   ▼
~GLFWRuntime()                       ← glfwTerminate（进程级，仅一次）
   │
   ▼
进程退出
```

每个资源的「生」和「死」都有明确的、唯一的主人——这就是工程化的生命周期管理。

---

## 6.8 小结

- 资源分两级：**进程级**（init/terminate）和**窗口级**（create/destroy）。规则：terminate 归进程，destroy 归窗口。
- 推荐用 `GLFWRuntime`（或 App 层）独占 init/terminate，配引用计数支持库嵌套。
- 多窗口：`pollEvents` 进程级调一次，渲染前 `makeContextCurrent` 切上下文；要共享 GL 资源用共享上下文。
- 线程铁律：GLFW 调用只在主线程，一个上下文只 current 在一个线程。

## 📝 参考答案

### 1. `GLFWRuntime` + 双窗口

```cpp
class GLFWRuntime {
    static int s_count;
public:
    GLFWRuntime() {
        glfwSetErrorCallback(errorCallback);
        if (!glfwInit()) throw std::runtime_error("GLFW init failed");
        ++s_count;
    }
    ~GLFWRuntime() { if (--s_count == 0) glfwTerminate(); }
    GLFWRuntime(const GLFWRuntime&) = delete;
    GLFWRuntime& operator=(const GLFWRuntime&) = delete;
};
int GLFWRuntime::s_count = 0;

int main() {
    GLFWRuntime runtime;
    auto w1 = Window::create({ "Main",  800, 600 });
    auto w2 = Window::create({ "Tools", 400, 600 });
    while (w1 || w2) {
        if (w1 && w1->shouldClose()) w1.reset();
        if (w2 && w2->shouldClose()) w2.reset();
        if (w1) { w1->makeContextCurrent(); renderRed();  w1->swapBuffers(); }
        if (w2) { w2->makeContextCurrent(); renderBlue(); w2->swapBuffers(); }
        glfwPollEvents();      // 进程级，一次
    }
}
```

### 2. `makeContextCurrent`（验证「渲染前切上下文」）

```cpp
// Window 接口：virtual void makeContextCurrent() = 0;
// GLFWWindowImpl：
void makeContextCurrent() override { glfwMakeContextCurrent(m_window); }
```

验证：注释掉 `w2->makeContextCurrent()`，会发现画到 w2 的内容跑到 w1 上（或失效），证明切换是必须的。

### 3. 给窗口子系统加事件 + 输入 → 迷你引擎骨架

```cpp
auto w = Window::create({ /*...*/ });
w->setEventCallback([](Event& e){
    EventDispatcher d(e);
    d.dispatch<WindowResizeEvent>([](auto& ev){
        glViewport(0, 0, ev.getWidth(), ev.getHeight()); return true;
    });
    d.dispatch<KeyPressedEvent>([&](auto& ev){
        if (ev.getKeyCode() == KEY_ESCAPE) w->setShouldClose(true);
        return false;
    });
});
Input::setPoller(new GLFWInputPoller((GLFWwindow*)w->getNativeWindow()));
// 主循环：Input::nextFrame() → pollEvents → onUpdate → render → swap
```
