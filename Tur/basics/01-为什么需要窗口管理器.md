# 01 · 为什么需要窗口管理器

> 目标：搞清楚「封装一层 Manager」到底解决了什么问题。这一篇几乎没有代码，
> 但它决定了后面所有代码为什么这么写。

---

## 1.1 先看现状：脚本式代码长什么样

你现在 `src/main.cpp` 大概是这样（已精简）：

```cpp
#include <GL/glew.h>
#include <GLFW/glfw3.h>

void display(GLFWwindow*, double) {
    glClearColor(1.0, 0.0, 0.0, 1.0);
    glClear(GL_COLOR_BUFFER_BIT);
}

int main() {
    if (!glfwInit()) { exit(EXIT_FAILURE); }
    glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 4);
    glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 1);
    glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);

    GLFWwindow* window = glfwCreateWindow(600, 600, "Demo", NULL, NULL);
    glfwMakeContextCurrent(window);
    if (glewInit() != GLEW_OK) { exit(EXIT_FAILURE); }

    while (!glfwWindowShouldClose(window)) {
        display(window, glfwGetTime());
        glfwSwapBuffers(window);
        glfwPollEvents();
    }
    glfwDestroyWindow(window);
    glfwTerminate();
}
```

能跑。教程第一章到第三章这样写完全没问题。**但当你开始做引擎**，这段代码会迅速腐烂。

---

## 1.2 五个会爆炸的痛点

### 痛点 1：`glfw*` 调用散落在业务代码各处

你要加个按键退出、加个鼠标拖拽、加个窗口缩放处理……每加一个功能，`main` 里就多一行 `glfwSetXxxCallback`。
半年后你的渲染循环里夹杂着 30 行窗口 API，**业务逻辑和窗口库死死耦合**。

### 痛点 2：资源释放全靠人肉记忆

`glfwCreateWindow` 要配 `glfwDestroyWindow`，`glfwInit` 要配 `glfwTerminate`。
一旦函数中间某个分支 `return` 了，或者抛了异常，**配对的清理就漏了**——轻则内存泄漏，重则驱动报错。

### 痛点 3：错误处理只能 `exit(EXIT_FAILURE)`

`exit()` 直接干掉进程。引擎里你也许想：弹个错误框、回退到软件渲染、记录日志……全都被 `exit` 堵死了。

### 痛点 4：换不了窗口库

某天你想：
- 上 SDL2（跨平台更省心）、
- 或者用各平台原生 API（Win32 / Cocoa / X11）做定制标题栏，
- 或者把窗口跑在 WebGL/Emscripten 上。

结果发现 `glfw` 这个词在代码里出现了 50 次。**换库 = 重写一半项目**。

### 痛点 5：没法测试、没法复用

想写个单元测试验证「按 ESC 会触发关闭」？你得真的开一个窗口、真的按键盘。
因为输入逻辑和窗口逻辑和渲染逻辑全黏在 `main` 里，**没有任何东西是可以单独测的**。

---

## 1.3 引擎式的答案：一层 Manager

把所有和「窗口」相关的脏活脏活收进一个类 `GLFWManager`：

```
┌─────────────────────────────────────────────┐
│  你的游戏 / 引擎核心                         │
│  （只认识“窗口”这个抽象概念）               │
│        ▲                                    │
│        │  window.swapBuffers()              │
│        │  window.pollEvents()               │
│        │  window.isKeyPressed(KEY_A)        │
│        ▼                                    │
├─────────────────────────────────────────────┤
│  GLFWManager  ← 这一层把 GLFW 藏起来        │
├─────────────────────────────────────────────┤
│  GLFW（C API）                              │
│  glew / OpenGL 驱动                         │
└─────────────────────────────────────────────┘
```

对应到上面五个痛点：

| 痛点 | Manager 怎么解 |
|---|---|
| API 散落 | 只暴露 `swapBuffers() / pollEvents()` 等语义方法，`glfw*` 全在 `.cpp` 内部 |
| 释放靠人肉 | **RAII**：构造获取资源、析构自动释放，异常安全 |
| 只能 exit | `init()` 返回 `bool`，失败交给调用方决定 |
| 换不了库 | 进阶篇把它升级成 `Window` **接口**，换实现不动核心 |
| 没法测试 | 输入抽成事件 / 查询接口，可 mock、可单测 |

---

## 1.4 一个直观对比

**改写前**（你的循环里到处是 GLFW）：

```cpp
while (!glfwWindowShouldClose(window)) {
    if (glfwGetKey(window, GLFW_KEY_ESCAPE) == GLFW_PRESS)
        glfwSetWindowShouldClose(window, GLFW_TRUE);
    display(window, glfwGetTime());
    glfwSwapBuffers(window);
    glfwPollEvents();
}
```

**改写后**（业务代码完全不提 GLFW）：

```cpp
while (!window.shouldClose()) {
    if (window.isKeyPressed(Key::Escape))
        window.setShouldClose(true);
    render();
    window.swapBuffers();
    window.pollEvents();
}
```

注意：除了循环变干净，更重要的是——**未来你想把 GLFW 换成 SDL，这段循环一个字都不用改。** 这就是抽象的回报。

---

## 1.5 小结

- 引擎开发的本质之一是**控制复杂性**，而控制复杂性的头号武器是**分层 + 封装**。
- 窗口管理器不是「多此一举的封装」，而是把「易错的资源生命周期 + 易散落的 C API」收进一个边界清晰的类。
- 一个设计良好的 Manager 应该满足：**上层不需要 `#include <GLFW/glfw3.h>` 也能用窗口。**

## 📝 参考答案

> 答案不唯一，下面是参考实现与解析。

### 1. 数 `main.cpp` 里的 `glfw` 调用

照上面 1.1 节的精简 `main` 逐行数：

| 行 | 调用 |
|---|---|
| `glfwInit()` | 1 |
| `glfwWindowHint(...)` ×3 | 3 |
| `glfwCreateWindow(...)` | 1 |
| `glfwMakeContextCurrent(...)` | 1 |
| `glfwWindowShouldClose(...)` | 1 |
| `glfwGetTime()` | 1 |
| `glfwSwapBuffers(...)` | 1 |
| `glfwPollEvents()` | 1 |
| `glfwDestroyWindow(...)` | 1 |
| `glfwTerminate()` | 1 |

共 **12 处**，每一处都是封装候选点——全部应消失进 `GLFWManager::` 方法里，让业务代码零 `glfw` 依赖。

### 2. 自己设计 `GLFWManager` 公开接口

```cpp
class GLFWManager {
public:
    bool init(const Props& props);
    void shutdown();
    void pollEvents();
    void swapBuffers();
    bool shouldClose() const;
    void setShouldClose(bool v);
    int  width() const;
    int  height() const;
    void setVsync(bool enabled);
    bool isKeyPressed(int key) const;
    void setKeyCallback(KeyCallback);
    void setResizeCallback(ResizeCallback);
    GLFWwindow* nativeHandle() const;
};
```

核心原则：**接口里不出现一个 `glfw`**。和 [04 篇 4.1](04-实现基础GLFWManager.md) 对照，思路一致。
